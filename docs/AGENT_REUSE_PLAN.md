# Atelier Agent 复用与实施清单

更新日期：2026-10-21。本文是全项目的 Agent 复用子计划；总范围见 [全项目开发文档](PROJECT_DEVELOPMENT.md)，续接先读 [nextStep.md](../nextStep.md)。完成状态必须以源码和实测验证为准。

## 1. 用户目标与当前边界

把 ShellPilot 已有的对话、模型协议、工具调用审批、上下文压缩、历史恢复和长期记忆能力适配到 Atelier。保留 Atelier 浅色 React 界面，工具面向画布、图片、视频、素材和积分。

当前 Atelier 对话页是浏览器内存 Mock，关键词匹配和定时回复不是真实 Agent；此前固定 token 数字已移除；当前不展示虚构用量。ShellPilot 有可复用实现，但不是已解耦的通用 SDK。不得把提取代码、契约或测试通过标为 Atelier 用户功能已经接通。

用户要求：先写本清单，再实现；每完成一项更新标记、代码位置和验证结果；不打包。保留所有既有修改。用户后续已授权本次初始化、提交并推送 Atelier 仓库；不公开部署，不读取用户真实模型密钥。

## 2. 换电脑／新会话怎么继续

1. 找到本项目根目录（包含 `apps/web`、`services/api`、`docs`）；不依赖原电脑的 `E:` 盘符。
2. 先读根目录 `AGENTS.md`、`nextStep.md`、`docs/PROJECT_DEVELOPMENT.md`、本文件与 `docs/AGENT_PROGRESS.md`，再核对实际源码、文件差异和开发环境。
3. 按总计划和 nextStep 决定的顺序执行，下方 R 编号是稳定任务 ID，不是强制执行顺序；任务涉及的文档“下一步”比旧聊天记录可靠，但不能替代实际代码核对。
4. 如果有 Git，运行 `git status --short` 并保护原有修改。接手时目录不是 Git 仓库；本次按用户要求初始化并推送，实际状态见 nextStep。文档不会自动同步，换电脑需克隆/拉取完整项目。
5. 必须携带源码、文档、迁移、测试、`package-lock.json`、Cargo lockfiles 和 `third_party` 来源记录；不必携带 `node_modules`、`target`、`dist`、`.idea`。不要复制 `.env` 中的密钥、生产数据库或浏览器本地数据。
6. 安装前端依赖用 `cd apps/web` 后 `npm ci`；Rust 使用 stable，本机验证为 1.99；crate 声明的最低版本未单独验收。开发 PostgreSQL 配置见 README 和 `infra/compose.yaml`。
7. 优先执行本文复验命令，再改代码。离线依赖不足时记录实际缺项；原电脑的依赖缓存不是跨电脑能力。
8. 结束前更新本清单阶段标记、进度文档的最新快照、运行结果、未通过项和下一项，避免仅在聊天中交接。

建议给新会话的指令：

> 继续 Atelier 开发。先读 AGENTS.md、nextStep.md 和全项目开发文档，再核对 Agent 子计划与源码。当前先管理端供应商/模型，再用户端普通对话，之后接历史/压缩和画布，注册与积分放后面。每步确认通过后更新 nextStep.md，不打包。

## 3. 来源及架构决策

ShellPilot 来源相对目录：`../ai-ssh-terminal-server-rust`、`../ai-ssh-terminal-client`；不同电脑位置可不同，优先按下表与提取清单找代码，不硬编码磁盘路径。

核对时 Rust HEAD：`3756e8f7655697443641e5a8ed0704d2cb4da615`。来源工作区同时有其他未提交修改；本任务不修改来源仓库。已提取文件逐项记录原文件 SHA256、适配说明与许可证，后续迁移再次核对。

| 能力 | ShellPilot 位置 | Atelier 适配点 |
|---|---|---|
| 模型与流式协议 | `src/agent/provider/` | 可移植请求与响应；服务端凭据、供应商配置，禁止前端持有 Key |
| 会话生命周期 | `src/agent/chat.rs`、`turns.rs`、`repository.rs` | PostgreSQL、服务端用户身份、请求幂等、取消和恢复 |
| 工具循环与校验 | `src/agent/tool_loop.rs`、`tool_loop/schema.rs`、`strict_json.rs` | 通用注册表和创作工具执行器；保留严格参数检查 |
| 审批 | `src/agent/approvals.rs`、`extensions/approval.rs` | 将 SSH 目标改为用户/项目/操作参数/报价版本绑定 |
| 上下文预算与压缩 | `src/agent/budget.rs`、`compact.rs`、`compact/auto.rs` | 完整请求成本、完整工具交互组、摘要证据、版本提交与失败恢复 |
| 长期记忆 | `src/agent/memory.rs` | 用户确认的偏好/经验；用户与项目范围替换服务器范围 |
| UI 与状态 | 客户端 `components/AgentPanel.tsx`、`AgentExecution.tsx`、`AgentContextStatus.tsx`、`AgentMemory.tsx`、`state/conversationRuns.ts` | 保留逻辑，解除组件/UI/全局状态耦合；Tauri IPC 改 HTTP + SSE |

采用逐步提取：在 Atelier 内建立独立的 `crates/atelier-agent-core`，纯逻辑不依赖 Axum、数据库、Tauri 或 SSH。短期这是有来源记录的提取副本，不是两个产品已经共同依赖的共享库；稳定后再讨论独立仓库/统一包及回接 ShellPilot。

- API 宿主负责认证、PostgreSQL、事件传输、模型密钥、工具实际执行和积分事务。
- 核心负责预算、严格参数校验、后续的协议/轮次/审批规则；模型输出不能自行注册工具或扩大权限。
- 前端负责展示真实事件、操作审批、历史和上下文状态，不计算可信余额，不自行认定工具执行成功。
- 意图由主模型结合业务提示词和实际工具决定；不迁入旧 Java 分类缓存，不把当前关键词 Mock 当分类器。
- 长记忆只保存明确确认的偏好和经验，摘要不能自动变成长记忆，也不能继承审批授权。
